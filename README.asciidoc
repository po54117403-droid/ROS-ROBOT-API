diff_drive — 差速驱动控制器
该软件包实现了ROS节点，用于控制和监控差动驱动机器人。

包装 旨在比ROS控制器框架更轻量级，尽管其性能更低 性能，因为它是用 Python 编写的。如果你需要紧凑、实时的控制，你可能会想要 看ros_controllers， 这是C++包，包含一个与ros_control和controller_manager集成的差动驱动控制器。这些控制器是专门设计的 在同一过程中与硬件集成，而不是使用主题。相反，这个包裹 期望通过标准ROS消息发布所需的电机转速。

供给节点
diff_drive_controller——将电机的扭转速度转换为车轮速度。

diff_drive_odometry—— 发布基于车轮编码器数据的里程计。

diff_drive_go_to_goal——将机器人移动到目标位置。

diff_drive_mock_robot—— 实现了一个模拟差动驱动机器人，用于测试。

本套件中的节点设计时考虑了以下因素：

节点和实现差分驱动器的硬件应仅处理编码器刻度。

物理坐标的转换应在本包中的节点内进行。

该软件包应能与导航栈干净整合，或许还能通过重新映射实现。

节点应使用导航栈使用的标准主题和参数名称，但应允许重新映射。

演示
要查看该包中所有节点的运行，你可以从 ROS 启动演示。没有 除了标准ROS包之外的依赖。

roslaunch diff_drive demo.launch
这会作为演示的一部分启动rviz，并显示机器人位置为一个小坐标系 0.25米的网格。在rviz中，你可以通过点击顶部工具面板中的2D导航目标按钮来移动机器人。 然后在网格内点击并拖曳，设置机器人的目标位置和航向。模拟机器人将移动到 那个新姿势，你可以通过机器人斧头的运动看到。

演示中允许前进和后退移动，如果目标位置在机器人后方， 它会向后移动。你只能通过将参数设置为 来强制机器人前进。~forwardMovementOnlytrue

参数

每米行程编码器滴答次数。

2. diff_drive_odometry
监听车轮运动并进行评分，并发布 odom 框架与机器人框架之间的变换。

已发表主题
~odom——（nav_msgs/里程计）
机器人里程计——当前机器人姿势。

~tf
里程计框架和机器人框架之间的变换。

订阅主题
~lwheel_ticks（std_msgs/Int32）
左轮累计编码器滴答。

~rwheel_ticks（std_msgs/Int32）
右轮累计编码器滴答。

~lwheel_rate（std_msgs/Float32）
左轮转速，以编码器每秒的刻数表示。

~rwheel_rate（std_msgs/Float32）
右轮转速，以编码器每秒的刻数表示。

参数
~ticks_per_meter（双重）
每米行程编码器滴答次数。

~wheel_separation（双重）
两个轮之间的距离（m）。

~rate（双倍，默认10.0）
和主题的发布速率（Hz）。tfodom

~timeout（双倍，默认0.2）
收到扭转消息后继续发布所需轮子速率的时间（秒数）。 如果设置为零，只有在收到新的扭转消息时才会发送轮速。

~base_frame_id（字符串，默认：“base_link”）
机器人基础框架的名称。

~odom_frame_id（字符串，默认：“odom”）
里程参考系的名称。

~encoder_min（整数，默认：-32768）
~encoder_max（int，默认：32768）
编码器应该输出的最小值和最大值。用来计算里程计数，当数值绕行时。

~wheel_low_wrap（int，默认值：0.3 * （encoder_max - encoder_min + 1） + encoder_min）
~wheel_high_wrap（int，默认：0.7 * （encoder_max - encoder_min + 1） + encoder_min）
如果读数大于wheel_high_wrap，下一个读数小于wheel_low_wrap，则读数已绕正方向，里程计数将被适当计算。同样的道理也适用于负面方向。

3. diff_drive_go_to_goal
监听新的目标姿态，并计算实现目标所需的速度。

已发表主题
~distance_to_goal（std_msgs/Float32）
距离目标位置（米）。

~cmd_vel（geometry_msgs/扭转）
目标姿势所需的线速度和角速度。

订阅主题
~goal（geometry_msgs/姿势）
想要的目标姿势。

参数
~rate（浮点，默认：10）
发布所需速度（Hz）的速率。

~goal_linear_tolerance（float，默认：0.1）
假设机器人已到达目标位置的距离（米）。

~goal_angular_tolerance（float，默认值：0.087）
机器人角度与目标姿态角度的差值，假设机器人在该角度下具有 实现目标姿态（弧度）。默认温度大约是5度。

~max_linear_velocity（浮点数，默认：0.2）
目标方向的最大线速度（米/秒）。

~max_angular_velocity（浮点，默认：1.5）
最大角速度（弧度/秒）。

~max_linear_acceleration（浮点，默认：4.0）
最大线加速度（米/秒^2）。

~forwardMovementOnly（布尔值，默认：真）
如果属实，则只能向前移动以达到目标位置。 如果是假，机器人会向后移动到目标，如果那是最大数 直线路径。

~Kp（float，默认：3.0）
线性距离比例常数。数值越高，机器人向目标加速越快，减速越慢。

~Ka（float：默认：8.0）
角度与球门位置的比例常数。数值越高，机器人转向速度越快，朝目标方向转动。

~Kb（float：默认：-1.5）
角度与目标姿势方向的比例常数。数值越高，机器人越能快速转向目标姿势方向。根据自主移动机器人，这个数值应为负数。

确定线速度和角速度以朝目标移动的控制定律如下。设 d 为距离目标。设a为机器人航向与目标位置之间的夹角，其中左边为正。设b为目标方向与最终姿态角度之间的夹角，其中左侧为正。然后计算机器人的线性速度和角速度如下：

v = Kp * d
w = Ka*a + Kb*b
参见Siegwart等人著作《自主移动机器人》第二版。第3.6.2.4条。在这个代码中，当机器人 距离目标足够近，v设为零，w则简单地等于Kb*b。

为了确保目标趋同，Kp以及Ka必须是正的，Kb必须为负，且Ka必须大于Kp.为了确保稳健的收敛，使机器人永不改变方向，Ka- 5/3*Kb- 2/π*Kp必须大于零。

4. diff_drive_mock_robot
实现完美差动驱动机器人硬件的模拟。它紧接着任何速度 以无限加速接收的命令，并发布轮式编码器值和编码器 利率。

已发表主题
~lwheel_ticks（std_msgs/Int32）
左轮累计编码器滴答。

~rwheel_ticks（std_msgs/Int32）
右轮累计编码器滴答。

~lwheel_rate（std_msgs/Float32）
左轮转速，以编码器每秒的刻数表示。

~rwheel_rate（std_msgs/Float32）
右轮转速，以编码器每秒的刻数表示。

订阅主题
~lwheel_desired_rate（std_msgs/Int32）
期望的左轮转速，单位为编码器每秒的刻数。

~rwheel_desired_rate（std_msgs/Int32）
期望右轮转速，单位为编码器每秒刻数。

参数
~cmd_timeout（浮点数，默认：0.2）
机器人在最后一个轮速信息后自动停止的时间（秒）。

~rate（float，默认10.0）
模拟轮编码器值和速率应公布的速率（Hz）。
